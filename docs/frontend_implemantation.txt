LEGACY MODERNIZATION GATEWAY
FRONTEND IMPLEMENTATION PLAN (END-TO-END)
===========================================================


PROJECT GOAL
===========================================================

Build a modern enterprise-style dashboard that visually demonstrates:

1. Legacy system chaos
2. Middleware transformation
3. API normalization
4. AI field mapping
5. System resilience
6. Real-time observability

The frontend is NOT just UI.

It is:
------------
The storytelling engine of the project.

Judges should understand the project within 30 seconds
just by looking at the dashboard.



===========================================================
FRONTEND OBJECTIVES
===========================================================

The frontend must achieve these 5 goals:

1. VISUALIZE THE PROBLEM
--------------------------------
Show ugly legacy data formats.

2. VISUALIZE THE TRANSFORMATION
--------------------------------
Show clean normalized REST output.

3. VISUALIZE SYSTEM INTELLIGENCE
--------------------------------
Show AI schema mapping.

4. VISUALIZE RELIABILITY
--------------------------------
Show retries, cache hits, failures.

5. LOOK ENTERPRISE-GRADE
--------------------------------
Dark theme
Professional cards
Real-time metrics
Clean layout
Modern animations

Why:

- Fast setup

- Huge ecosystem
- Easy hackathon development
- Modern frontend standard

Why:

- Enterprise credibility

- Easy responsive design
- Minimal CSS writing

===========================================================
2. LEGACY DATA VIEWER
===========================================================

Purpose:
---------
Show ugly legacy system responses.

Features:
----------
- syntax highlighting
- broken formatting
- malformed fields
- random failures
- timeout simulation

Example:
----------
LEFT PANEL:

CUST_ID|CUST_NM|ACT_FLG
101|JOHN|Y

or

<REC>
 <CID>101</CID>
</REC>

This creates visual contrast.



===========================================================
3. CLEAN API RESPONSE VIEWER
===========================================================

Purpose:
---------
Show normalized modern API response.

Features:
----------
- pretty JSON
- syntax highlighting
- REST schema
- validation badges

Example:
----------
{
  "customerId": 101,
  "name": "John",
  "status": "ACTIVE"
}

Visual Goal:
-------------
Transformation should feel magical.



===========================================================
4. AI MAPPING VISUALIZER
===========================================================

Purpose:
---------
Show semantic field transformations.

Layout:
---------
Legacy Field       →      Modern Field

CUST_NM            →      customerName
ACT_FLG            →      isActive
DT_JOIN            →      joinedAt

Features:
----------
- animated arrows
- confidence score
- AI mapping explanation

This is one of the biggest WOW factors.

===========================================================
API CONTRACTS
===========================================================


GET /legacy/raw/{source}
------------------------------------------------
Returns ugly data.


GET /api/customers/{source}
------------------------------------------------
Returns clean normalized JSON.


GET /metrics
------------------------------------------------
Returns:
- request count
- failures
- retries
- cache hits


GET /health
------------------------------------------------
Returns service status.


GET /transformations
------------------------------------------------
Returns field mappings.
